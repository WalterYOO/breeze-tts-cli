# breeze-tts-cli (`btts_cli`)

A local voice-design workbench and reproducible request runner for
**Breeze TTS 2** on Apple Silicon (MPS). It turns the manual loop of
"write an instruction → generate seeds/cfg grids → compare → freeze a voice"
into a small, scriptable command chain.

```
design init → design lint → design explore → design report
            → design freeze → voice add/list/show → say
```

## Install

```bash
# Python 3.10–3.12. Base install does not pull torch.
pip install -e ".[dev]"

# Local inference extras (torch 2.9.1 / transformers 4.57.3 / qwen-tts 0.1.1)
pip install -e ".[mps]"

# Optional objective metrics (F0 / HNR / spectral centroid)
pip install -e ".[metrics]"
```

The model directory is **not** shipped with this package and is never copied
into it. Point the CLI at a local Breeze-TTS-2 checkpoint:

```bash
export BTTS_MODEL_DIR=/path/to/Breeze-TTS-2
# or pass --model /path/to/Breeze-TTS-2 to individual commands
```

Expected checkpoint layout:

```
Breeze-TTS-2/
  config.json
  generation_config.json
  tokenizer.json
  tokenizer_config.json
  model.safetensors.index.json
  model-0000*-of-0000*.safetensors
  audio_tokenizer/{config.json,model.safetensors}
```

## Quick start

```bash
# Check the machine, model files, license, and (optionally) benchmark
btts_cli doctor
btts_cli doctor --bench --json

# Create and lint an editable design description
btts_cli design init dusk.yaml
btts_cli design lint dusk.yaml --show-rendered

# Generate the default 2 seed x 2 cfg matrix (4 takes, ~1.5 min on MPS)
btts_cli design explore dusk.yaml --out runs/dusk-01

# Objective metrics, CSV/Markdown, one reel, and an offline audition page
btts_cli design report runs/dusk-01 --metrics full

# Freeze the chosen take as a replayable design recipe
btts_cli design freeze runs/dusk-01 --take c001 --name dusk --as design

# Or freeze it as a clone reference (requires human transcript confirmation)
btts_cli design freeze runs/dusk-01 --take c001 --name dusk --as clone --confirm-transcript

btts_cli voice list
btts_cli voice show dusk

# Three say routes
btts_cli say "欢迎收听今晚的节目。" --design dusk.yaml
btts_cli say "欢迎收听今晚的节目。" --voice @dusk
btts_cli say "欢迎收听今晚的节目。" --voice @dusk --direction "更轻、更慢，带一点笑意"
```

## Commands (P0)

| Command | Purpose |
|---|---|
| `doctor [--bench] [--json]` | Environment, model files, MPS, memory, license; optional load + short-generation benchmark |
| `design init FILE [--template T] [--language zh\|en]` | Write an editable design YAML |
| `design lint FILE [--show-rendered]` | Offline, deterministic Instruction Readiness Score |
| `design explore FILE --out RUN_DIR [--resume] [--wide]` | Generate candidates; atomic WAV + recipe sidecar per take |
| `design report RUN_DIR [--metrics basic\|full]` | Metrics, CSV, Markdown, `all_candidates.wav`, offline HTML |
| `design freeze RUN_DIR --take ID --name NAME [--as design\|clone]` | Freeze a take into a voice profile |
| `voice add NAME --ref WAV --text FILE --confirm-transcript` | Add a clone profile from authorized reference audio |
| `voice list` / `voice show NAME` | Inspect the local voice store |
| `say TEXT --design FILE` | `tts_instruction`, cfg 4.0 |
| `say TEXT --voice @NAME` | `ref_clone_tata` (clone) or stored design recipe; cfg 1.0 for clone |
| `say TEXT --voice @NAME --direction TEXT` | `ref_edit_tata`, cfg 4.0 |

Default explore matrix: `seeds=42,43 × cfg=2.5,4.0` = **4 takes**.
`--wide` adds a second cover script = **8 takes**. Explicit matrices above 16
takes must be requested with `--seeds`/`--cfgs` and `--yes`.

## Design YAML

```yaml
schema_version: 1
name: dusk
language: zh
template: zh-late-night-radio/v1

identity:
  age: 30s
  gender_presentation: female
  timbre: [warm, clean, slightly_husky]
  pitch: low_mid
  articulation: clear, relaxed
  persona: late_night_host

delivery_baseline:
  pace: medium_slow
  energy: medium_low
  tone: calm, intimate

scene:
  proximity: close_mic
  room: dry_studio

avoid: [childlike, shouting]
covers:
  - "晚上好，欢迎收听今天的节目。"
  - "外面下着雨，我们慢慢聊。"
```

The compiler stores the user intent (`structured`), the exact string sent to
the model (`rendered_instruction`), and `compiler_version`.

## Design vs clone

Breeze has no saveable voice prompt. A generation is
`instruction + text + seed + cfg + model digest`.

- **`design` profile** stores the instruction, seed, cfg and a preview. It
  replays the recipe, but the same instruction may drift across texts.
- **`clone` profile** stores a reference WAV plus its exact transcript. This is
  the stable identity anchor across texts (`ref_clone_tata`) and the recommended
  choice for a production character.
- **Direction** (`ref_edit_tata`) is a one-off performance note and is never
  written into voice identity.

Freezing as clone requires `--confirm-transcript`; the CLI prints the source
text so a human can check for missing or added words. Reference audio should be
6–20 s; under 6 s warns, over 30 s requires `--allow-long-ref`.

## Data and outputs

- Voice store: `$BTTS_DATA_DIR/voices` or the platform user-data dir
  (`~/Library/Application Support/btts_cli/voices` on macOS).
- `design explore` writes `runs/<run>/run.json`, `candidates/<take>.wav` and
  `<take>.recipe.json`. Each completed take is written atomically; `--resume`
  only fills missing or hash-mismatched takes.
- `design report` writes `report/metrics.csv`, `report/report.md`,
  `report/all_candidates.wav` and `report/audition.html`.
- `say` writes `outputs/say-*.wav` plus a recipe sidecar unless `--out` is
  given.
- Sidecars and profiles never contain tokens, private URLs, or absolute paths.

## Metrics are not a judge

`design report` measures duration, clipping, silence, and — in `full` mode —
median F0, HNR and spectral centroid. These are for **eliminating and sorting**
technical failures. They are not an aesthetic score; the final pick is human.

## Tests

```bash
ruff check .
pytest                         # fake engine only, no MPS required
BTTS_RUN_MPS=1 pytest -m mps   # real model load + three say routes
```

`tests/test_wheel_contents.py` builds a wheel and asserts it contains no
weights, no `audio_tokenizer/`, no `ms-models/`, and includes all license files.

## Vendored inference code

Only the MPS-required subset of upstream `breezeblue-ai/breeze-tts` is copied,
with package-qualified imports, under `src/btts_cli/_vendor/breeze_tts/`.
`vendor.lock.json` pins the upstream commit and hashes;
`scripts/sync_breeze_vendor.py --check` verifies the tree, and
`--ref <commit>` performs an explicit upgrade. See `THIRD_PARTY_NOTICES.md`.
